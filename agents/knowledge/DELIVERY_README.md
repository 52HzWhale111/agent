## 二、每个东西是什么、怎么用

### 1. Prompt模板（01_Prompt模板）

**这是你最核心的交付物。** 三条链路每个都有一个完整的Prompt模板，包括：
- 角色设定
- 规则约束（防止大模型瞎编）
- 输入输出格式
- 实际使用示例

**怎么用**：
1. 打开对应的md文件，把 `{}` 里的占位内容替换成实际数据
2. 把Prompt发给大模型API（比如豆包、GPT）
3. 拿到返回结果

**注意**：每个Prompt模板文件里都写了注意事项，比如"输出必须是JSON"、"不许用外部知识"这些约束，别删。

---

### 2. 测试案例集（02_测试案例集）

**这是你的第二个交付物。** 20个案例全部整理好了，每个都有标准答案要点：
- 概念问答 8个：问题 + 考察知识点 + 标准答案要点 + 预期出处
- 需求拆解 6个：输入需求 + 应该输出几个角色/用例/异常流
- 文档评审 6个：输入文档 + 应该查出几个问题（对应8号给的埋雷文档）

**怎么用**：
1. 把每个案例的输入，喂给你的Agent
2. 把Agent的输出，和"标准答案要点"对比
3. 判断过没过，填到测试记录里

**合格标准**：
- 概念问答：知识点对、出处准、没瞎编 → 过
- 需求拆解：角色/用例/异常流够、JSON格式对 → 过
- 文档评审：检出率 ≥ 80%，误报率 ≤ 20% → 过

---

### 3. 测试记录模板（03_测试记录）

**这是你的第三个交付物。** 跑完20个案例后，把结果填到这个表格里。

**需要填的内容**：
- 每个案例过了还是没过
- 没过的话，为什么没过（检索没召回到？Prompt约束不够？模型理解错了？）
- 最后写一个改进计划

### 4. 代码骨架（04_代码）

这是给后端2对接用的接口骨架，你可以自己往里填实现：

#### knowledge_retriever.py
- 简单的关键词检索器，不用向量数据库，小组作业够用
- 用法：输入问题 → 返回最相关的3-5个知识点
- 你需要做的：把8号给的60个知识点，全部导入到 `KNOWLEDGE_BASE` 列表里

#### agent_api.py
- FastAPI写的接口骨架，三条链路各一个接口：
  - `POST /qa` — 概念问答
  - `POST /analyze_requirement` — 需求拆解
  - `POST /review_document` — 文档评审
- 后端2直接来调这些接口就行
- 你需要做的：把 `TODO` 注释的地方，填上实际的大模型调用逻辑
