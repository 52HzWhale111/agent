# 文档评审测试案例（6个）

每个案例包含：输入文档、应该查出的问题清单（标准答案）。

## DR-01 校园失物招领需求规格说明书（DEF-01）

- **输入**：DEF-01_埋雷版_校园失物招领.md
- **预期查出的问题（标准答案清单）**：
  1. **缺章节**：缺少"非功能需求"章节
  2. **缺章节**：缺少UML用例图章节
  3. **空话**："系统性能要好"没有量化指标
  4. **空话**："界面要美观"没有具体标准
  5. **空话**：功能需求描述太简略，没有输入输出和异常处理
- **考察点**：能不能查出缺章节和空话

## DR-02 登录功能需求（DEF-03）

- **输入**：DEF-03_埋雷版_登录功能需求.md
- **预期查出的问题（标准答案清单）**：
  1. **空话**："登录系统要安全"没有说明怎么安全（密码加密？验证码？）
  2. **空话**："登录界面要友好"没有具体要求
  3. **缺章节**：缺少异常情况处理（密码错误怎么办？账号被锁定怎么办？）
  4. **粒度问题**：把"点击登录按钮"这种UI操作当成了功能需求
- **考察点**：能不能识别空话、能不能发现异常流缺失

## DR-03 ATM取款用例（DEF-04）

- **输入**：DEF-04_埋雷版_ATM取款用例.md

## 测试说明

- 每个案例跑完后，检查三点：
  1. **检出率**：标准答案里的问题，Agent查出了几个？（比如标准答案5个问题，查出了3个，检出率60%）
  2. **误报率**：Agent查出的问题里，有多少是对的？有多少是吹毛求疵？
  3. **分类对不对**：把"缺章节"错标成"空话"、把"图文不符"错标成"缺章节"，都算不合格
- 合格标准：检出率 ≥ 80%，误报率 ≤ 20%
- 常见失败情况：
  - 只能查出明显的缺章节，查不出隐藏的空话 → 检出率低
  - 把很多正常的描述也当成空话 → 误报率高
  - 问题类型标错 → 分类不合格
