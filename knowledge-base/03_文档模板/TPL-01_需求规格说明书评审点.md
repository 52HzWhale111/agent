# TPL-01 需求规格说明书评审点

**依据**：教材第7章信息栏“软件需求规格说明模板”，PDF第93-94页；课件6.pdf第93-94页。
**老师会看的核心结构**：引言（背景/目标用户） -> 总体描述（功能概览/运行环境） -> 功能需求（角色/用例/主异常流） -> 非功能需求（性能/安全） -> 验收标准。

**文档评审评分点（Agent查错清单）：**
1. **项目背景**：是否有项目背景、目标用户与使用场景。
2. **需求组织**：功能需求是否按角色或用例进行组织。
3. **流程完整性**：每条核心功能是否有主流程和异常流（不能只写正常情况）。
4. **非功能需求**：是否可量化测试（不能只写“界面友好”“性能良好”）。
5. **图文一致**：用例图中的角色，是否与文字描述完全一致。
6. **类图对应**：是否有核心类图，类名和文字是否一致。
7. **验收标准**：每条需求能否对应一个具体的验收检查方法。
8. **测试章节**：是否有测试相关章节（测试范围、测试方法、验收标准）。
9. **术语一致性**：术语前后是否一致（比如“用户”和“学生”不能混用）。
10. **空话检查**：是否排除了“系统应尽量方便”“界面应美观大方”等主观废话。
