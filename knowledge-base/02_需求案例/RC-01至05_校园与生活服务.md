# 需求案例集：校园与生活服务（RC-01 至 RC-05）

## RC-01 校园失物招领系统
- **背景**：学生丢失或捡到物品，需要发布信息并审核认领。
- **角色**：学生、管理员。
- **功能需求**：发布失物/招领、按关键词查找、提交认领申请、管理员审核。
- **非功能需求**：认领申请2秒内反馈；联系方式仅管理员和失主可见。
- **主流程**：发布失物 -> 他人查找 -> 提交认领申请 -> 管理员审核 -> 归还物品。
- **异常流**：1. 重复认领（提示已有申请，转仲裁）；2. 误领（撤销认领并通知原主）；3. 缺联系方式（拒绝提交）。
- **标准答案要点**：必须有管理员审核环节；必须考虑重复认领和误领的异常处理。

## RC-02 图书管理系统
- **背景**：学校图书馆借还书及库存管理。
- **角色**：读者、图书管理员。
- **功能需求**：扫码借书、还书、查询库存、逾期罚款计算。
- **非功能需求**：并发借书时库存不能扣减为负数；系统响应时间<1秒。
- **主流程**：读者选书 -> 管理员扫码 -> 系统扣减库存 -> 借阅成功。
- **异常流**：1. 库存不足（提示无法借阅）；2. 读者有逾期未还记录（拒绝借阅）；3. 扫码失败（手动输入ISBN）。
- **标准答案要点**：要体现库存扣减的原子性（并发控制）；必须包含逾期罚款规则。

## RC-03 学生选课系统
- **背景**：高校学生每学期在线选择课程。
- **角色**：学生、教师、教务处管理员。
- **功能需求**：查看课表、选课、退课、教师录入成绩、管理员发布课程。
- **非功能需求**：选课高峰期支持5000人同时在线不崩溃。
- **主流程**：学生登录 -> 查看可选课程 -> 提交选课 -> 系统校验并生成课表。
- **异常流**：1. 课程名额已满；2. 上课时间冲突；3. 学分超出上限；4. 未修先导课程。
- **标准答案要点**：核心是校验逻辑（时间冲突、余量、学分）；必须考虑高并发。

## RC-04 校园通讯录
- **背景**：在校师生查询校内人员联系方式。
- **角色**：普通师生、系统管理员。
- **功能需求**：按姓名/院系查询、拨打电话（一键呼叫）、导入导出通讯录。
- **非功能需求**：保护个人隐私，非公开号码需权限申请才能查看。
- **主流程**：输入姓名 -> 检索数据库 -> 显示部门及联系方式 -> 点击拨打。
- **异常流**：1. 查无此人（提示重试）；2. 号码已停机（提示停机）；3. 无权限查看（弹窗申请权限）。
- **标准答案要点**：隐私保护机制是重点；要处理查无结果的空状态。

## RC-05 宠物医院预约
- **背景**：宠物主人带宠物看病，需要提前预约。
- **角色**：宠物主人、医生、前台。
- **功能需求**：选择医生、选择时间段、填写宠物信息、取消预约。
- **非功能需求**：同一医生同一时段不能被重复预约。
- **主流程**：选医生 -> 选时间 -> 填宠物信息 -> 支付挂号费 -> 预约成功。
- **异常流**：1. 医生临时停诊（系统发短信通知并退款）；2. 超时未支付（自动取消名额）。
- **标准答案要点**：重点处理医生排班冲突和未支付释放名额的逻辑。
