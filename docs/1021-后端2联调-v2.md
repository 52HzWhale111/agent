powershell -NoProfile -ExecutionPolicy Bypass -File infra/start-local.ps1 -MockAgents -WithBackend

此命令启动真实业务后端8001、网关8000、知识Mock 8100及工程Mock 8200。已有旧Mock进程时，先用stop-local.ps1停止本项目进程，再按上面方式启动；不要直接占用别人的8200服务。重启单个网关也要传-MockAgents -WithBackend -Service gateway，避免误切回无业务认证的独立模式。

业务演示账号由后端1初始化：demo_new、demo_student、demo_weak，演示密码和用途见backend/README.md。本地脚本保存独立的开发签名密钥及业务SQLite于忽略目录data/local/backend，不提交Git。生产初始化不创建演示账号。

打开 http://127.0.0.1:8001/docs ，执行POST /api/v1/auth/login，复制data.access_token；打开 http://127.0.0.1:8000/docs ，点Authorize填入Token后调用Agent/任务接口。网关也代理/api/v1/*与/business/*，业务接口保留原code/message/data/request_id外壳、HTTP状态与文件下载响应。

## 认证、文件与任务

设置BACKEND_URL后，Agent API用Bearer Token调用业务/api/v1/auth/me确认当前用户；不把GATEWAY_API_KEY当学生身份，不接受前端user_id冒充他人。网关files/tasks表新增可空owner_id，旧表自动添加字段；旧无所有者任务不会向登录用户开放。查询他人的任务返回404，未登录返回401。

POST /api/uploads在业务联调模式下转发到后端1的POST /api/v1/documents，避免再建一套业务文档。兼容返回file_id与document_id（值相同），并附document元数据。也可直接使用业务上传接口；列文档、下载原文件均走业务接口，由后端校验所有者。

启动评审时三种输入只能选一个：

```json
{"document_id":"业务上传返回的id","doc_type":"srs"}
```

也兼容file_id表示该业务文档ID；或直接传content。网关先用当前Token读取文档元数据及授权原文件，将只读任务副本保存在网关随机路径，再把正文提取和Agent处理放入队列。Token不写入任务数据库，副本仍记录owner_id。docx/pdf支持正文提取，doc须先转换；不能让前端传任意服务器磁盘路径。首个202响应前包含授权下载耗时，后续正文提取和Agent调用在60秒执行预算内。

任务终态仍为succeeded/failed；succeeded表示上游返回了结果，并不表示文档没有缺陷或代码测试全部通过。按task_id每2秒查询，检查result中的领域状态。任务结果只能由提交者读取。

业务服务会生成自己的request_id；网关记录双方编号映射。直接业务代理响应另附X-Backend-Request-ID，X-Request-ID为网关入口编号，原业务响应正文不改写。

## 工程服务：已适配实际协议

对外仍调用网关POST /api/code-tests：

```json
{"code":"public class Calculator { public int add(int a,int b){return a+b;} }","tests":"import org.junit.jupiter.api.Test; import static org.junit.jupiter.api.Assertions.*; public class CalculatorTest { @Test void addTest(){assertEquals(3,new Calculator().add(1,2));} }","language":"java"}
```

网关返回202及任务号，worker改为向工程服务POST /sandbox/run-tests发送Content-Type:text/plain;charset=utf-8，正文为code + 换行---TEST---换行 + tests，不再向/run_tests发送JSON。

result原样保留status、tests.success/failed、coverage.line、output。SUCCESS/FAILED/COMPILE_ERROR/TIMEOUT/NO_TESTS是领域结果；服务内部ERROR转为失败任务SANDBOX_ERROR。Mock专用status=MOCK、覆盖率及计数为null，不能作为编译成功证据。

当前工程接口要求学生代码与JUnit测试源码都存在；缺测试或提交ZIP项目会返回422 CODE_AND_TESTS_REQUIRED。网关仍可上传/保存ZIP，但不声称工程服务已支持多文件ZIP执行。源码含保留分隔符---TEST---会被拒绝，避免错误拆分。

工程PR没有/check_consistency或/health；网关的一致性入口明确返回503 FEATURE_UNAVAILABLE，不伪造空问题列表。工程连通探测用OPTIONS /sandbox/run-tests的204响应，在/health/ready标为http_route_only，仅说明路由可达，不证明Docker镜像、沙箱隔离或执行器就绪。

## 工程执行尚需核验的问题

PR #5 README只给端口和本地Maven启动命令，没有可直接访问的远程主机/IP。当前本机已安装Java、Maven和WSL Docker，新增本地入口跑通真实Java/JUnit；不再依赖工程同学提供远程地址来验收本地沙箱。

原始源码与README有以下差异。原文件保持不变；新增SandboxServerLocal已修复本地路径、测试限时和容器回收，以下原始入口仍须对照处理：

- SandboxServer.java把临时目录固定为D:/work/agent/agent/agents/sandbox/tmp，部署到其他电脑或Linux前应改为可配置路径。
- HTTP服务的JUnit执行命令没有timeout 5，且先阻塞读完进程输出再waitFor(60)。遇到不退出的进程，外层网关超时不能保证后台Docker容器已停止；需要执行器自己限时并销毁对应容器。
- README列出的TIMEOUT、细粒度分支定位、图代码一致性、ZIP项目等不能仅凭接口骨架判为已验收；当前返回主要是测试计数、行覆盖率和原始控制台输出。
- Dockerfile是预装JUnit/JaCoCo的执行镜像，不是监听8200的HTTP服务镜像；部署不能把它直接当成可启动API服务。

本机真实联调使用SandboxServerLocal，网关SANDBOX_AGENT_URL仍为http://127.0.0.1:8200。切换远程工程服务时再填写对应地址。网关超时120秒和测试JVM5秒是不同约束，不能互相替代。

## UML与业务功能

业务/api/v1/diagrams已可保存及读回class/use_case/sequence，nodes用label/position/properties，边用source/target/type等字段。PUT必须携带base_version，409 VERSION_CONFLICT应交给前端处理，网关不吞掉冲突或自动覆盖。标准schema见docs/uml-schema.md；工程尚无比对接口，因此现阶段只完成保存/版本链路。

学情来自后端1的真实选择题记录，前三薄弱点与五道推荐可通过代理读取。Agent活动不会自动写成对错学习记录，需后续确定评分证据，不能用Mock结果造学习数据。
