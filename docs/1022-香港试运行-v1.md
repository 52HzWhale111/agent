## 如何测试

1. 在业务 Swagger 展开 `POST /api/v1/auth/register`，点击 Try it out，填写自己的 `username`、`password` 和 `display_name`。用户名用 3–32 位字母、数字或下划线，密码至少 8 位。生产没有公开的默认学生密码。
2. 使用 `POST /api/v1/auth/login` 登录，复制返回的 `data.access_token`。在两个 Swagger 页各自点击 Authorize，填 JWT 本体，页面会自动加 `Bearer`。不要把 DeepSeek Key 或运维密钥填入学生登录。
3. 业务页可测试知识点、案例、练习判分、学情、文档和 UML 版本。业务页已配置 `/business` 前缀；前端直接使用统一域名下的 `/api/v1/*` 即可。
4. 网关页的 `POST /api/qa` 示例：`{"question":"软件配置管理中的基线是什么意思？"}`。检查 `answer` 与 `sources`；资料缺口以外部补充来源单独标注，不冒充教材章节。
5. `POST /api/requirements/analyze` 提交 `{"description":"做一个校园失物招领系统"}`，检查 actors、use_cases、main_flow、exception_flow。
6. `POST /api/uploads` 上传可提取文字的 DOCX/PDF，取 `document_id`；向 `POST /api/reviews` 提交 `{"document_id":"实际ID","doc_type":"srs","scope":"excerpt"}`。整篇文档用 `full`，节选用 `excerpt`。返回 202 后，用 `GET /api/tasks/{task_id}` 轮询至 succeeded 或 failed。学生只能读取自己的文档和任务。
7. 沙箱通过 `POST /api/code-tests` 提交 `code` 与 `tests` 字符串，202 后轮询任务。可用 `gateway/smoke_sandbox.py` 内的 Calculator 示例；正常结果为 SUCCESS、JUnit 1 项成功、行覆盖率 100%。编译错误和测试失败属于已执行的结果，应展示 result.status，不应只看外层任务 succeeded。

所有学生请求使用 `Authorization: Bearer <业务JWT>`。`/health/ready` 使用单独运维凭据，不是公开的学生健康接口。不要在聊天、代码或截图中公布 Key、JWT 和数据库密码。

## 模型试运行额度

模型仍为官方 `deepseek-flash`，对应已核实的 DeepSeek-V4.1-Flash-1017。最终评审复核使用 high 思考模式。为遵守本轮模型测试最多 1 元的授权，香港知识容器启用了 `infra/cloud_knowledge.py`：

- 整台部署最多 8 次官方模型 HTTP 请求，包含内部重试；一次文档评审通常使用 2 次。
- 请求 JSON 最多 20,000 UTF-8 字节、最多 3 条纯文本消息；单次最大输出 8,192 tokens。长文档在试运行期间可能被拒绝。
- 只允许官方 HTTPS chat/completions 与 Flash 模型，不接受搜索工具或其他计费模型参数。
- 请求发出前，在宿主 `/opt/zhigou/model-budget` 独占创建计数文件。请求失败仍消耗一个名额；容器重启不清零，额度耗尽后不再转发。
- 按核实时的高峰价格输入 2 元/百万 tokens、输出 8 元/百万 tokens，并预留每次 2,048 个消息封装 tokens，8 次保守上界为 **0.877056 元**。这是保守上界，不是实际账单；定价变化后必须重新核算。

定价来源：[DeepSeek 模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。预算目录缺失或不可写时调用失败，不会自动创建新的额度。不要删除计数文件或换空目录来“修复”额度不足；扩大试用范围、调整限制和重新授权预算需由负责人决定。

## 实际部署与复现

香港 Ubuntu 22.04，2 核 4GiB、40GiB 系统盘；项目目录 `/opt/agent`。Docker Engine 与 Compose 已启用。业务使用 PostgreSQL，网关使用持久 SQLite/任务卷；证书、原文档和数据库使用独立持久卷。应用只公开 HTTP/HTTPS，网关 8000 绑定回环；8100、8200、5432 不向公网发布。

本轮使用 `infra/docker-compose.cloud.yml` 和 `infra/Caddyfile.cloud`，不需要尚未交付的 FRONTEND_IMAGE，也不接入占位前端。云端业务设置 `--root-path /business`，避免 Swagger 请求错误的 OpenAPI 地址。该配置固定项目路径 `/opt/agent`，迁移位置时应先改构建和挂载路径。

复现时由管理员在服务器准备根目录 `.env`（权限 600，勿提交），按 `.env.example` 填写 DOMAIN、强随机 GATEWAY_API_KEY、POSTGRES_PASSWORD、JWT_SECRET_KEY、LLM 三项和 SANDBOX_WORK_DIR。云端配置不使用 FRONTEND_IMAGE 或 ACME_EMAIL。

```sh
sudo install -d -m 700 -o root -g root /opt/zhigou/sandbox-work
sudo install -d -m 700 -o 10001 -g 10001 /opt/zhigou/model-budget
chmod 644 infra/cloud_knowledge.py infra/Caddyfile.cloud
# 确认 .env 中 SANDBOX_WORK_DIR=/opt/zhigou/sandbox-work
sudo env ZHIGOU_COMPOSE_FILE=infra/docker-compose.cloud.yml sh infra/deploy.sh
```

首次限额目录只在初次部署时准备；已有部署不得重置。服务均使用 unless-stopped，Docker 自启动后可恢复；管理员主动 stop 的容器须手动 start。

## 备份和监控

已配置 `zhigou-backup.timer`，每天北京时间 03:15；`zhigou-backup.service` 的 cloud.conf 设置 `ZHIGOU_COMPOSE_FILE=infra/docker-compose.cloud.yml`。首次手动执行成功，包含 PostgreSQL、网关 SQLite/任务文件、业务原文档及 SHA-256 校验。基础脚本仍默认使用原完整 Compose，其他环境不受影响。

```sh
sudo systemctl list-timers zhigou-backup.timer
sudo systemctl start zhigou-backup.service
sudo journalctl -u zhigou-backup.service -n 30 --no-pager
sudo env ZHIGOU_COMPOSE_FILE=infra/docker-compose.cloud.yml sh infra/backup.sh
```

备份在 `/opt/agent/backups/`，现为同机备份；异机加密副本仍待配置。恢复时还需保留模型限额目录中已经消耗的名额，不能通过恢复旧计数重新获得费用授权。当前没有自动删除历史备份，应关注 40GiB 磁盘余量。

监控只检查实际上线的网关、知识、沙箱和业务服务，每项当前健康；没有配置通知接收地址时，故障/恢复只写容器日志，不会发送到团队群。运维管理目前可使用阿里云云助手和 Workbench；本机直连 SSH 在握手前断开，尚未把直连 SSH 可用作为交付结论。
