# 知构业务接口约定 v1

适用后端1、前端1、前端2与后端2的联调。基础地址为 `http://127.0.0.1:8000`，业务前缀 `/api/v1`。字段以同目录 `1021-openapi-v1.json` 和在线 `/docs` 为准，文档和建表SQL由实现导出。

## 认证与公共格式

注册与登录使用 JSON。登录成功后取 `data.access_token`，后续个人数据请求加入 `Authorization: Bearer <token>`。Swagger 点 Authorize 后粘贴 Token 本体。课程知识、案例和题目可公开读取；个人记录、图、文档必须认证。服务端只从 Token 确认所有者，不接受请求中的 user_id 覆盖身份。

```json
{"code":"OK","message":"成功","data":{},"request_id":"服务端生成的UUID"}
```

失败时仍使用同样外壳，`code` 是稳定业务错误码，HTTP 状态也表示失败。`data` 通常为 null；422 参数错误为字段与原因列表；图冲突为 `{"latest_version":2}`。每个请求生成 `X-Request-ID`，与响应中的 request_id 一致。分页数据为 `{"items":[],"total":0,"page":1,"page_size":20}`，page从1开始，page_size最大100。时间使用 ISO 8601 UTC，掌握度和错误率为0至1的小数，前端显示百分比时乘100。

## 接口清单

| 方法与路径 | 登录 | 请求要点 | 成功结果 |
| --- | --- | --- | --- |
| GET `/health` | 否 | 无 | 200 服务与数据库状态 |
| POST `/api/v1/auth/register` | 否 | username、password、display_name | 201 用户资料，不返回Token |
| POST `/api/v1/auth/login` | 否 | username、password | 200 access_token/token_type/expires_in/user |
| GET `/api/v1/auth/me` | 是 | Bearer | 200 当前用户 |
| GET `/api/v1/knowledge-points` | 否 | 可选chapter、keyword、page、page_size | 200 分页知识点 |
| GET `/api/v1/knowledge-points/{point_id}` | 否 | 如KP-33 | 200 知识点完整字段及原有来源 |
| GET `/api/v1/cases` | 否 | 分页 | 200 需求案例 |
| GET `/api/v1/cases/{case_id}` | 否 | 如RC-01 | 200 背景、角色、需求、流程及answer_points |
| GET `/api/v1/questions` | 否 | 可选knowledge_point_id，分页 | 200 选择练习，不含标准答案 |
| POST `/api/v1/learning/answers` | 是 | exercise_id、answer、client_event_id | 201 record、correct_option、explanation、replayed |
| GET `/api/v1/learning/records` | 是 | 分页 | 200 本人答题历史 |
| GET `/api/v1/learning/diagnosis` | 是 | 可选min_attempts，默认1 | 200 weak_points、mastery、recommended_questions等 |
| POST `/api/v1/diagrams` | 是 | title、diagram_type、data | 201 diagram_id、version=1、完整图 |
| GET `/api/v1/diagrams` | 是 | 分页 | 200 每张图的最新版本摘要 |
| GET `/api/v1/diagrams/{diagram_id}` | 是 | 可选version，省略读取最新 | 200 指定版本完整图 |
| GET `/api/v1/diagrams/{diagram_id}/versions` | 是 | 分页 | 200 版本摘要，版本倒序 |
| PUT `/api/v1/diagrams/{diagram_id}` | 是 | title、diagram_type、data、base_version | 200 追加后版本 |
| POST `/api/v1/documents` | 是 | multipart/form-data，字段file | 201 文档元数据 |
| GET `/api/v1/documents` | 是 | 分页 | 200 本人文档列表 |
| GET `/api/v1/documents/{document_id}` | 是 | 路径ID | 200 文档元数据 |
| GET `/api/v1/documents/{document_id}/content` | 是 | 路径ID | 200 原文件二进制，不使用JSON外壳 |

问答流式输出、需求拆解、文档评审任务、代码测试任务不是本服务接口，由后端2与对应Agent约定。不能把普通知识点查询当成已实现Agent问答。历史页目前可按答题、图、文档分别查询，暂无跨Agent任务的统一历史接口。

## 字段与调用示例

### 注册与登录

注册示例：`{"username":"student_01","password":"Student@2026","display_name":"同学"}`。用户名3至32个ASCII字母、数字、下划线，统一为小写；密码8至128字符；昵称1至64字符且不能全为空白。登录只发送用户名和密码。有效期默认7200秒，可由ACCESS_TOKEN_MINUTES配置；无刷新Token接口，过期后重新登录。

```powershell
$login = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8000/api/v1/auth/login' -ContentType 'application/json' -Body '{"username":"demo_weak","password":"Demo@2026!"}'
$headers = @{ Authorization = 'Bearer ' + $login.data.access_token }
Invoke-RestMethod -Uri 'http://127.0.0.1:8000/api/v1/learning/diagnosis' -Headers $headers
```

### 知识点与案例

知识点字段：`id,title,chapter,definition,example,common_mistake,source,tags,difficulty,related_features,source_file`。chapter是课程分组1至8，source保留原资料的教材或课件定位，不能把两者混为一谈。keyword匹配标题或定义，`%`和`_`按普通字符处理。

案例和练习共有 `id,kind,title,knowledge_point_ids,content,source_file`。需求案例是kind=case，content保留原文和各字段，详细结构可读取RC-01查看；开放式答案要点通过案例详情的answer_points提供。案例没有原始知识点关联时数组为空，不推测标签。单选题是kind=question，content含 `prompt` 与 `options:[{"id":"A","text":"选项内容"}]`；后端自编练习的来源标明为自编示范，不能冒充教材原题。

### 答题与学情

```json
{"exercise_id":"Q-01","answer":"A","client_event_id":"attempt_20261021_0001"}
```

answer必须为题目现有选项。每次真实作答生成新事件号，网络重试复用原事件号；同一用户同事件同题同答案返回原记录且replayed=true，仍为201；同事件换答案或换题返回409。客户端不能提交is_correct、knowledge_point_ids或其他未声明字段。作答反馈中的record包含作答时的知识点标签、正确性和创建时间。

`GET /learning/diagnosis`返回：total_records、correct_records、weak_points（最多3个）、mastery（含60个知识点）、recommended_questions（最多5道）和推荐原因。每点字段为knowledge_point_id、title、attempts、errors、error_rate、mastery。错误率为errors/attempts，掌握度为1减错误率；同一记录关联多个知识点时每点各计一次。同率按作答次数降序，再按知识点ID升序。排序使用未四舍五入的比率。

未作答点的error_rate和mastery为null，不进入薄弱排名；min_attempts筛选进入排名的最低次数，不会删除历史记录。推荐按薄弱点优先级、同级未答优先、题目ID排列，不足5道时补其他题。该指标是当前示范题库上的正确率，不能宣称等同于学生能力的全面测量。模型、文档与代码活动尚不自动产生可评分学习记录；后续需与Agent约定评估结果来源和事件幂等后扩展。

### 图数据

完整结构见[UML数据约定](uml-schema.md)。三种图类型为class/use_case/sequence。每次保存必须完整发送画布JSON及title，PUT还需要base_version。服务端保留nodes/edges及属性、位置、metadata。前端保留本地未保存内容，收到409后展示冲突提示；重新读取后人工合并。切换图类型需新建，不能原图变更类型。

### 文件上传

使用multipart的file字段，单文件上限20MiB（20×1024×1024字节），只接受doc/docx/pdf/zip，验证基础文件签名与docx必要条目。客户端提供的Content-Type不作为唯一判断依据。文件以随机键保存，返回id、original_name、media_type、size_bytes、sha256、status、created_at，不返回磁盘路径。status=uploaded仅表示上传完成，不表示评审完成。

后端2集成时可直接代理该上传接口，再用document_id启动评审任务，避免重复维护两套文档记录。网关/反向代理还须对请求体总量、连接时间和并发设置限制；应用的文件流限制是在multipart解析后执行，不能替代入口流量限制。工作节点访问文件应走经过授权的下载接口或双方明确的受控存储协议，不能按任意前端路径读服务器文件。

## 错误码

| HTTP | code | 前端建议 |
| --- | --- | --- |
| 401 | AUTH_REQUIRED / TOKEN_INVALID / INVALID_CREDENTIALS | 提示登录或认证失败 |
| 409 | USERNAME_EXISTS | 更换用户名 |
| 409 | EVENT_CONFLICT | 检查是否错误复用了答题事件号 |
| 409 | VERSION_CONFLICT | 保留编辑，读取最新版本后合并 |
| 404 | KNOWLEDGE_NOT_FOUND / CASE_NOT_FOUND / QUESTION_NOT_FOUND | 提示课程条目不存在 |
| 404 | DIAGRAM_NOT_FOUND / DOCUMENT_NOT_FOUND | 提示不存在或不可访问，不展示他人对象信息 |
| 404 | DOCUMENT_FILE_MISSING | 原文件缺失，联系维护人员 |
| 413 | FILE_TOO_LARGE | 压缩或换更小文件 |
| 415 | FILE_TYPE_UNSUPPORTED / FILE_CONTENT_INVALID | 更换允许格式的有效文件 |
| 422 | VALIDATION_ERROR / ANSWER_INVALID / FILENAME_INVALID / DIAGRAM_TYPE_IMMUTABLE | 按字段原因修正请求 |
| 503 | DATABASE_UNAVAILABLE | 显示暂不可用与重试入口 |
| 500 | INTERNAL_ERROR | 记录request_id并提示稍后重试 |
| 其他 | HTTP_ERROR / NOT_FOUND | 显示通用请求错误，不把接口错误当成空数据 |

服务响应不会回显密码输入。Swagger中的401/404等通用错误响应是统一格式说明；每个操作实际可能返回的业务错误码以上表与具体实现为准。
