## 2 本地复现

`backend/README.md`提供从空环境安装的完整步骤，根目录`run-local.ps1`提供演示启动入口。以下命令全部从仓库根目录执行，首次使用先按运行说明创建虚拟环境并安装依赖：

```powershell
.\.venv\Scripts\python.exe backend\scripts\manage.py init-db --demo
.\.venv\Scripts\python.exe backend\scripts\manage.py export
.\.venv\Scripts\python.exe -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000
```

然后打开：

- Swagger UI：`http://127.0.0.1:8000/docs`
- OpenAPI：`http://127.0.0.1:8000/openapi.json`
- 健康检查：`http://127.0.0.1:8000/health`

健康检查成功只证明业务服务与其数据库连通，不证明 Agent、前端、网关或公网部署已经可用。默认本地数据使用 SQLite，不需要模型 API Key。PostgreSQL 部署需设置对应 `DATABASE_URL`，并在实际数据库环境重新执行初始化和回归。

在根目录执行自动化检查：

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
```

演示数据仅在明确启用 `--demo` 时准备。三个演示账号为 `demo_new`、`demo_student`、`demo_weak`，演示密码均为 `Demo@2026!`。这些账号用于空状态、一般学习历史和明显薄弱点演示，不用于生产账户。重复导入不应重置学生已有记录。

## 3 前端 1 字段联调

### 3.1 先完成认证与统一响应

`POST /api/v1/auth/login` 接收 JSON，不使用 OAuth2 表单。成功结果中的 `data.access_token` 用作后续 `Authorization: Bearer <token>`。Swagger 中点击 Authorize，填入获得的 Token；不要把密码填到 Bearer Token 框。

响应主体统一采用以下字段；原文件下载成功时返回二进制文件，不套 JSON：

```json
{
  "code": "OK",
  "message": "成功",
  "data": {},
  "request_id": "服务端生成的请求标识"
}
```

前端同时检查 HTTP 状态与 `code`。普通列表在 `data` 中返回 `items`、`total`、`page`、`page_size`。空列表是成功状态，不能被显示成接口失败。记录错误时保存 HTTP 状态、业务代码和 `request_id`，不要记录密码或完整 Token。

| 页面或操作 | 业务 API | 前端必须处理的行为 |
| --- | --- | --- |
| 注册与登录 | `/auth/register`、`/auth/login`、`/auth/me` | 重复用户名提示；Token 失效重新登录 |
| 课程资料 | `/knowledge-points`、`/knowledge-points/{point_id}`、`/cases`、`/cases/{case_id}` | 按分页读取；知识点 `source` 为原资料出处文字 |
| 文档列表与上传 | `/documents`、`/documents/{document_id}` | 上传用 multipart 字段 `file`；列表为空显示“还没有记录” |
| 下载原文 | `/documents/{document_id}/content` | 带鉴权获取文件；不要拼出服务器存储路径 |
| 练习与作答 | `/questions`、`/learning/answers` | 题面不包含标准答案；提交后显示评分与解析 |
| 学习历史 | `/learning/records` | 当前用户分页列表；重试不重复插入页面记录 |
| 学情 | `/learning/diagnosis` | `mastery=null` 表示未知；最多三个薄弱点；显示推荐原因 |
| 图列表 | `/diagrams` | 仅显示每张逻辑图最新版本；进入画布后再读完整数据 |

表中的路径统一前缀为 `/api/v1`。完整参数、字段和错误代码查看接口约定及 OpenAPI，不能根据页面中文标签自创另一组字段名。

### 3.2 答题事件号

每次用户真实点击提交时生成新的 `client_event_id`；同一请求超时重试时复用原值。该值为 8–64 个字母、数字、下划线或连字符。请求示意如下，题目 ID 和选项应来自实际题面：

```json
{
  "exercise_id": "Q-01",
  "answer": "A",
  "client_event_id": "practice_20261021_0001"
}
```

后端决定对错与知识点标签。客户端不能上传 `is_correct` 来影响学情，也不能将学生重新作答误当作网络重试。相同事件相同内容返回 `replayed=true`；相同事件不同内容返回冲突。

### 3.3 空状态与学情解释

`demo_new` 没有答题数据，其 `weak_points` 为空，未学习知识点的 `mastery` 和 `error_rate` 为 `null`。可以展示基础练习，但不显示“你的三个薄弱点是……”之类结论。有记录账号按错误率排序；显示百分比时由前端统一保留精度，不改变原始计数。

图表选择展示五个知识点时，应根据课程页面需要选取数据，并保留未学习状态。学情接口返回的掌握度是题库作答正确率，不应在页面写成经验证的能力评分。

## 4 前端 2 图数据联调

先验证完整 JSON 往返，再做页面布局与颜色。创建图使用 `POST /api/v1/diagrams`；成功返回的 `diagram_id` 是后续读取和保存的逻辑 ID，`version` 是当前版本。

```json
{
  "title": "图书借阅类图",
  "diagram_type": "class",
  "data": {
    "nodes": [
      {
        "id": "class_book",
        "type": "class",
        "label": "Book",
        "position": {"x": 100, "y": 100},
        "properties": {"attributes": ["isbn: String"], "methods": ["borrow()"]}
      },
      {
        "id": "class_reader",
        "type": "class",
        "label": "Reader",
        "position": {"x": 420, "y": 100},
        "properties": {"attributes": ["studentId: String"], "methods": []}
      }
    ],
    "edges": [
      {"id": "edge_borrow", "source": "class_reader", "target": "class_book", "type": "association", "label": "借阅"}
    ],
    "metadata": {}
  }
}
```

更新使用 `PUT /api/v1/diagrams/{diagram_id}`，请求字段与创建相同，另外加入 `base_version`。例如基于 v1 编辑时提交 `base_version: 1`，成功后返回 v2。将同一请求再发一次会产生版本冲突，前端需提示学生重新读取或合并，不能无限自动重试。

| 需要验证的操作 | 调用与检查 |
| --- | --- |
| 再次打开 | GET `/diagrams/{diagram_id}`，核对位置、属性和连线 |
| 版本列表 | GET `/diagrams/{diagram_id}/versions`，显示当前账号可见的版本 |
| 查看历史 | GET `/diagrams/{diagram_id}?version=1`，读取不改动当前版本 |
| 基于历史继续 | 将历史 JSON 放回编辑器，基于最新版本保存为新版本 |
| 非法图 | 重复 ID、悬空连线、NaN 坐标等应被拒绝，前端保留原编辑内容 |
| 改变图类型 | 同一逻辑图不能由类图直接变成时序图；需要创建新图 |

节点与边 ID 在同一张图中必须共同唯一；最多 500 个节点、1000 条边，JSON 大小上限为 2 MiB。后端保存可扩展 `properties`，但不负责自动布局、PNG/SVG 导出或图代码语义对齐。现有六张 PNG 示例仅用于展示，演示 JSON 是单独准备的可编辑数据。

## 5 后端 2 接入与部署交接

1. 将业务 API 作为单独服务接入，不把 Agent 超时任务塞进数据库读写请求。网关调用业务接口时透传学生 Bearer Token。
2. 上传链路在集成后统一入口。独立后端已提供上传与存储；网关应转发到该能力或与后端 1 明确约定唯一存储流程，避免网关和业务服务各存一份互不一致的文件。
3. 文档评审以受控的文档 ID 和经过验证的用户身份关联原文件。不要向 Agent 暴露整个私有上传目录，不把用户输入当作服务器路径。
4. 设置 PostgreSQL、上传持久卷和稳定 JWT 密钥。生产环境必须配置足够长度的随机签名密钥；修改密钥会使既有 Token 失效。
5. 将前端实际域名加入 `CORS_ORIGINS`。不要将本地访问成功当作跨域、HTTPS 或公网访问已验收。
6. 在入口服务器设置请求体限制；同时保留后端对文件大小、后缀和文件特征的检查。
7. 数据库和上传文件需要配套备份，单独备份元数据不能恢复丢失的原文件。备份频率、恢复演练与服务自启动由部署成员记录。
8. 以 `request_id` 关联业务错误。网关的 Agent 任务号、进度、超时和重试状态是另一套明确协议，不能复用图版本号或答题事件号。

本地已覆盖的业务功能与生产验证项应分别记录。生产环境至少重查登录、三类对象权限、上传下载、图冲突、答题幂等、数据库重启后的数据保留；服务端口对外开放、TLS、监控与备份恢复仍需部署环境证据。

## 7 测试与演示顺序

### 7.1 建议的四分钟业务演示

1. 使用 `demo_new` 登录，打开学情，展示空记录与基础练习，说明系统不会凭空生成薄弱点。
2. 查询一个知识点及来源，再打开 RC-01，展示结构化资料可以被页面和 Agent 共用。
3. 使用有记录账号读取一张类图，修改后保存，重新加载并查看前一版，展示数据确实落库。
4. 用旧 `base_version` 提交一次保存，展示 409 冲突与明确提示，说明不会覆盖新修改。
5. 提交一道练习并查看解析，再刷新学情，按知识点计数说明错误率；重放相同事件证明不会重复计数。
6. 上传合法课程文档并下载原件，切换另一账号验证无法访问该文档。

该演示只说明业务后端能力。完整五条产品链路、领域 Agent 定制前后对比与外网上线演示由团队组合完成。

## 8 本次作业可直接合并的后端说明

> 后端采用 FastAPI 与 SQLAlchemy，保存用户、知识点、案例与练习、文档、学习记录和 UML 图版本六类数据。课程资料使用知识工程提供的稳定编号导入，知识点保留出处，练习由服务端评分。学生每次作答关联知识点标签，系统按错误率、作答次数和知识点编号计算最多三个薄弱点，并推荐练习；未学习的数据保留为未知。UML 图保存节点、连线和布局，每次保存追加版本，并通过基础版本检查避免覆盖其他页面的新修改。私有文档、图和学习记录均按登录身份隔离。Agent 调用、异步任务与生产部署由接入层配合完成，领域定制效果通过团队实际运行的课程案例另外验收。

以上文字用于团队报告的后端方案说明。是否已上线、哪些测试通过、Agent 定制效果提升多少，必须使用实际结果补充，不能从设计文字推断。
